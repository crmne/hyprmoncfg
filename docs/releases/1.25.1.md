# hyprmoncfg 1.25.1

Enable a display even when its old position is occupied. The layout moves it into clear space, and applying the change wakes it before confirmation. These fixes work with the existing [panel 2.10.0](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.10.0); no panel update is needed.

Download the [Linux x86-64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.25.1/hyprmoncfg_1.25.1_linux_amd64.tar.gz) or [Linux ARM64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.25.1/hyprmoncfg_1.25.1_linux_arm64.tar.gz), or install `hyprmoncfg-bin` from the AUR.

## Fixed

- **Enable no longer gets stuck on an occupied position.** Enabling, moving, resizing, or unmirroring a display reflows collisions into clear space instead of rejecting the edit with an overlap error. Clear positions are preserved, and saved profiles stay unchanged until you save. The shared placement behavior serves both the panel and TUI. Reported and fixed by @crmne in [16cabd2](https://github.com/crmne/hyprmoncfg/commit/16cabd2308b1a233087981c4cfd81d8d47174798).
- **An enabled display wakes before confirmation starts.** If a display changes from disabled to enabled but stays asleep, apply sends targeted wake requests and checks its power state within the existing verification deadline. If it never wakes, the change rolls back. Other displays that were already enabled and sleeping stay asleep. Both Lua and legacy Hyprland configurations are supported. Reported and fixed by @crmne in [d3a504b](https://github.com/crmne/hyprmoncfg/commit/d3a504ba1728938ecd69d6d4e22de394b25f2575).

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then run `systemctl --user restart hyprmoncfgd.service`.

The IPC protocol remains version 1. Panel 2.10.0 receives these fixes through the backend; an older backend retains the previous behavior.

## What's tested

The full Go test suite, vet, builds, dependency checks, and apply/daemon/IPC race tests pass. Regression coverage includes collision reflow, targeted wake commands, ignored and failed wakes, rollback, and preserving sleep on other displays. Synthetic panel captures cover compact and expanded layouts and light and dark themes.

On real hardware, @crmne confirmed the LG 16MR70 disable/enable cycle works with the new build alongside an MSI MPG321UR-QD on Hyprland 0.56.2. The real hardware check used Lua configuration; legacy wake behavior has automated coverage.
