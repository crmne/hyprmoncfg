# hyprmoncfg 1.24.0

A display recovery release, and 2-in-1s and tablets now rotate properly. With aquamarine 0.15.0, the display library under Hyprland 0.56, a monitor that comes back after another was turned off can stay black at `0x0` until you log out. hyprmoncfg now recognises that and brings it back by itself. A monitor that comes back also shows the workspace it showed before, monitors that need a gentle wake get one after every display was off, and a monitor dropped to a lower refresh rate goes back to its saved settings once it is stable. Install from the AUR or download a package below. Pair it with [panel 2.9.0](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.9.0) for Omarchy, which adds the new rotation controls.

![The TUI's Display controls with separate Resolution and Refresh rows, and a 1.33x scale marked Blurry](https://raw.githubusercontent.com/crmne/hyprmoncfg/v1.24.0/docs/assets/images/releases/1.24.0-tui-resolution-refresh.png)

## New

- **2-in-1s and tablets rotate with the device** ([#90](https://github.com/crmne/hyprmoncfg/issues/90)). Set a built-in panel's Rotation to **Auto** in the TUI or the panel, and hyprmoncfgd turns it with the device using iio-sensor-proxy, with no script of your own. Monitors beside it move to stay touching, the touchscreen and pen turn with it, and Hyprland reloads keep the rotation instead of resetting it, which is what made hyprmoncfg fight rotation scripts. A convertible turns only while folded into a tablet, as GNOME does. The rotation the panel has when you choose Auto counts as upright, so panels mounted in portrait work too, and your saved profile always stays upright. **Rotation lock:** `hyprmoncfg rotation toggle` (bind it to a key), `L` in the TUI, or the Lock beside Auto in the panel holds the current rotation, and is remembered across restarts. If your panel turns against the device, `hyprmoncfg rotation direction reversed` fixes the direction. See [2-in-1s and tablets](https://hyprmoncfg.dev/two-in-one/). Reported by @xpusostomos.
- **A monitor stuck at `0x0` comes back without logging out.** aquamarine 0.15.0 never releases the kernel's display pipe (CRTC) of a monitor that disconnects. When a monitor comes back and is handed that pipe, the kernel rejects every mode, so it stays black or frozen. A common trigger is turning every monitor off and then turning one back on alone. When an awake monitor stays at `0x0` although it lists modes, and the kernel still drives a disconnected port, the daemon logs the cause and switches to a free console and back through systemd-logind, which needs no root. Hyprland then resets the kernel's display state and the daemon reloads it. You see a text console for about two seconds. If the monitor is still stuck, the next switch waits 30 seconds, doubling up to 10 minutes. aquamarine 0.15.1 fixes the bug itself ([hyprwm/aquamarine#386](https://github.com/hyprwm/aquamarine/issues/386)). See [displays stuck without a mode](https://hyprmoncfg.dev/daemon/#displays-stuck-without-a-mode).
- **A display that comes back shows the workspace it showed before.** When a display turns off, Hyprland moves its workspaces to the others, and when it returns it can land on its default workspace instead of the one you left it on. With workspace planning on, the daemon now remembers the last workspace of each display by hardware identity and shows it again after the layout applies, then puts focus and the cursor back where they were. A workspace that another display is showing, or that the profile assigns to another display, stays where it is. With the planner set to Off, for example alongside hyprland-virtual-desktops, the daemon doesn't touch workspaces.
- **Resolution and refresh rate are separate controls in the TUI.** Mode used to be one long list of every resolution and rate; a monitor like a 4K 144 Hz display lists 36. Now Resolution lists each resolution once, largest first, and Refresh is a row of the rates that resolution offers, such as `60Hz` `144Hz`, so switching between 60 and 144 Hz is one keypress. Changing the resolution keeps the rate when it can. Profiles store the same mode as before, and the panel gets the same controls.
- **The Scale row no longer jumps while you step through scales.** A scale that isn't one of the preset pills shows on the last pill instead of inserting a pill and resizing the row. A scale that gives fractional logical pixels is now called **⚠ Blurry**, in the TUI and the panel alike, which says what you will see.
- **Editors get scale advice from the daemon.** A new `scale_info` IPC method tells an editor which scales are sharp on a mode and the closest sharp one to any scale, so the panel no longer repeats hyprmoncfg's maths, and an edit can ask the daemon to snap a typed scale to the closest sharp one.
- **A lowered refresh rate is no longer permanent.** When the daemon has stepped a monitor down because it kept dropping at its saved settings, it now tries the saved refresh rate and VRR again after ten seconds at a usable mode. If the monitor can't hold them, it returns to the fallback and waits twice as long before the next try, up to five minutes, so a working screen isn't blanked over and over. The saved profile never changes.

## Fixed

- **A gentle wake works after every monitor was off.** A monitor remembered as needing a gentle wake (60 Hz with VRR off, then its saved settings) only had that rule ready while another monitor stayed connected. Turning off the last one left its high-refresh rule in place, so it woke straight into settings it can't wake at, often to no signal. The daemon now prepares the wake rule when no monitor is connected.
- **A gently woken monitor gets its saved settings only once it shows a picture,** after ten seconds with a usable mode, not merely ten seconds connected.
- **The stuck pipe no longer lowers a monitor's settings.** The daemon read the bug above as the monitor being unable to hold its mode and stepped it down to 60 Hz. It now leaves the settings alone when the cause is a stale pipe.

## Known limitations

- **Touch and pen rotation are global in Hyprland,** so an external drawing tablet turns with the built-in panel too.
- **The rotation direction is set from the command line only,** since it is calibration you set once. The guide also explains the system-wide fix for a wrong accelerometer mount matrix, which GNOME and KDE need too.
- **The console switch blanks every display for a few seconds** and needs logind to allow it for your session, which it does for the active local session. If it refuses, the log says so; switch by hand with `sudo chvt 2`, then back to your session's console, or update aquamarine.
- **The recovery runs only on the exact signature** of the aquamarine bug. A monitor stuck at `0x0` for another reason still needs a reconnect.

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

To get the aquamarine fix itself, update aquamarine to 0.15.1 or later and restart Hyprland. The IPC protocol is still version 1.

## What's tested

- **Automated tests** cover each change with a fake compositor, fake console and temporary files: the stuck-pipe signature and its backoff, the console switch followed by a reload that brings the layout back, no switch without a stale port, the sysfs check, the wake rule prepared with no monitor connected, the growing retry waits, and the workspace restore with its exceptions (shown elsewhere, assigned elsewhere, identical displays, planner off) for Lua and classic configs.
- **On real hardware:** an RTX 3090 (nvidia-open 610.57.04) with an MSI MPG321UR-QD and an LG 16MR70 on DisplayPort, Hyprland 0.56.2 and aquamarine 0.15.0. Both monitors off, then the MSI on alone: it stayed at `0x0`, the daemon switched consoles, and the desktop came back, then moved to 144 Hz with VRR. That run used a build that waited for a second failed apply before switching; the build that switches on the first failure, as this release does, then recovered the LG and the MSI the same way. Turning the MSI off and on, and both displays off and on, brought back each display's workspace; in those runs Hyprland already got it right, so the daemon's restore had nothing to do. The restore itself is covered by automated tests. On the same desktop, the panel's new Resolution and Refresh rows, Scale row, Custom… scale and Blurry marker were tried by hand, which found the Refresh row running off the panel with seven rates; it now wraps, as the TUI's always did.
- **Not tried:** AMD and Intel GPUs, docks and MST, which the upstream issue reports as affected too. Automatic rotation has not run on a real 2-in-1 or tablet yet: the sensor and tablet-mode switch are covered by tests with fakes, and the D-Bus calls follow iio-sensor-proxy's documented interface. Feedback is very welcome.
