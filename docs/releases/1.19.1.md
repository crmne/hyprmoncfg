# hyprmoncfg 1.19.1

A fix for closing the lid while docked, and a clearer way to turn the workspace planner off. This release goes together with [panel 2.4.1](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.4.1) for Omarchy.

## Closing the lid while docked settles again

In 1.19.0, some laptops kept flickering after the lid closed with an external display attached ([#72](https://github.com/crmne/hyprmoncfg/issues/72)). While Hyprland was turning the laptop screen off, it answered one of hyprmoncfg's checks slowly. hyprmoncfg took the slow answer as a failure and put the old layout back, which turned the laptop screen on again and started the next attempt.

Now hyprmoncfg keeps asking for up to three seconds after a reload before it decides anything. It only puts the old layout back when Hyprland says the new one didn't work, or when there's still no answer at the end. This helps any layout that turns a display off, not just closing the lid.

## Turn workspace rules off from Strategy

If another tool manages your workspaces, such as hyprsplit or [virtual-desktops](https://hyprmoncfg.dev/virtual-desktops/), set **Strategy** to **Off** in the Workspaces tab ([#70](https://github.com/crmne/hyprmoncfg/issues/70)). hyprmoncfg then writes no workspace rules for that profile.

- Strategy now goes Off, Manual, Sequential, Interleaved in both the TUI and the panel. The separate Enabled row is gone.
- Off keeps your plan. Pick a strategy again and your workspace count, group size and monitor order are still there.
- Profiles that already had workspace rules turned off open as Off. Nothing in your saved files changes.
- The TUI now writes strategy names the same way as the panel, for example Sequential instead of `sequential`.

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

The IPC protocol is still version 1. Panel 2.4.1 works with backend 1.19.0 or newer.

## What's tested

Automated tests cover slow checks after a reload, both for the Lua check and for reading the displays back, and the Off strategy in both editors. The lid fix hasn't been tried yet on a laptop that showed the flicker. If you saw it in 1.19.0, please say on [#72](https://github.com/crmne/hyprmoncfg/issues/72) whether 1.19.1 settles.
