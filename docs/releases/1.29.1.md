# hyprmoncfg 1.29.1

Choosing Auto rotation keeps the rotation you see, and moving a persistent planned workspace to another monitor works again on Omarchy.

Download the [Linux x86-64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.29.1/hyprmoncfg_1.29.1_linux_amd64.tar.gz) or [Linux ARM64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.29.1/hyprmoncfg_1.29.1_linux_arm64.tar.gz). On Arch, install `hyprmoncfg-bin` from the AUR.

## Fixed

- **Choosing Auto no longer turns a sideways panel the wrong way.** On a 2-in-1 whose sensor reads sideways while the laptop is upright, going from a fixed 270° to Auto could show 180° until you calibrated. Choosing Auto now takes the device's current position as upright, as **Calibrate** does, so the panel keeps the rotation it had. Normal back to Auto still restores your remembered upright rotation and leaves the calibration alone. This works the same in the TUI and the Omarchy panel, with no panel update needed. Reported by @xpusostomos in [#90](https://github.com/crmne/hyprmoncfg/issues/90).
- **Move workspace to … monitor works on persistent planned workspaces.** With Persistence set to All assigned, or for each display's default workspace under First per display, Hyprland moved the workspace back and left the target showing only the wallpaper. The move now pins the workspace to its new monitor for the rest of the session. Your saved profile is unchanged, and the next profile switch or reload puts it back where the plan says. Reported by @cemsbr in [#123](https://github.com/crmne/hyprmoncfg/issues/123).

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart `hyprmoncfgd.service`.

## Known limitations

- Choosing Auto uses the position you hold the device in at that moment. Hold it the way the current rotation looks right.
- A moved workspace stays on its new monitor until the generated file reloads. Re-applying an identical profile does not reload it.

## What's tested

The full Go suite, vet, and race tests for apply and the daemon pass. The rotation change has tests for the reporter's case (sensor sideways, fixed 270°, then Auto) through the daemon and the TUI, but it was not tried on a real 2-in-1. The workspace move ran in Lua against a stand-in for Hyprland's API, and in a nested Hyprland 0.56.2 with headless outputs: a persistent default workspace moved with a plain move went back when Hyprland rechecked its rules, while the pinned move stayed, and a reload restored the plan in both cases. It was not tried with Omarchy's own bindings on real monitors.
