# hyprmoncfg 1.30.0

Give every display workspaces of its own, the way Omarchy 4.5 and Niri do, on any distribution. This release also keeps your saved layout when you plug in another unit of the same monitor, keeps scale changes made with Omarchy's keys, and wakes displays again after resume on Hyprland 0.56.

Download the [Linux x86-64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.30.0/hyprmoncfg_1.30.0_linux_amd64.tar.gz) or [Linux ARM64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.30.0/hyprmoncfg_1.30.0_linux_arm64.tar.gz). On Arch, install `hyprmoncfg-bin` from the AUR.

## New

- **Per display workspaces.** A new workspace strategy gives each display its own workspaces 1-10: the first display in the monitor order gets 1-10, the next 11-20. `Super + number` goes to that workspace on the display you're on, `Super + Shift + number` moves the focused window there, and `Super + Shift + Alt + number` sends it without following. Choose it in the TUI or the Omarchy panel under Workspaces.
  - **On Omarchy 4.5 and later**, Omarchy already does this, so hyprmoncfg leaves it in charge: Omarchy's keys, hotplug handling and bar keep working as shipped, and hyprmoncfg writes no workspace rules. The planner shows which block Omarchy gives each display, read from Omarchy's own state.
  - **Everywhere else**, hyprmoncfg does it itself, with Lua bindings in the generated file or, for hyprlang configs, keys that run the new `hyprmoncfg workspace focus|move|move-silent <1-10>`.
  - **One profile works on both**, because the generated file checks for Omarchy when Hyprland loads it.
- **Omarchy's per-monitor workspaces stay on by default.** On Omarchy 4.5 and later, new profiles and layouts extended to a monitor no profile knows start with Per display. Before, plugging in an unfamiliar monitor switched workspaces to a global Sequential plan and turned Omarchy's per-monitor workspaces off. Elsewhere the default stays Sequential, and saved profiles keep the strategy they have.
- **Choose how many workspaces each display has**, from 1 to 10. The keys past the count do nothing, and on Omarchy hyprmoncfg takes just those keys back. Each display keeps its block of ten, so changing the count never renumbers a workspace.
- **Workspaces read 1-10 on every display.** The TUI's plan and canvas, the Omarchy panel and the [workspaces bar widget](https://github.com/crmne/omarchy-hyprmoncfg-workspaces) show the second display's workspace 11 as 1, as Omarchy's bar and the keys do. Window rules still use Hyprland's numbers, which the panel shows in parentheses.
- **Bars can show each display's own workspaces.** While a profile uses Per display, the daemon's status says which block each connected display owns and who runs them, so a bar doesn't have to read Omarchy's state. See `per_display_workspaces` in the [IPC reference](https://hyprmoncfg.dev/ipc/).
- **Omarchy's scale keys work with hyprmoncfg.** `Super + /` and `Super + Alt + /` now run the new `hyprmoncfg scale up|down`, which changes the focused display's scale through the daemon and saves it to the active profile. Scale changes made in Omarchy 4.5's display panel are picked up and saved too, instead of being overwritten by the next apply. `hyprmoncfg scale <scale>` sets an exact scale, snapped to one that is sharp on the display. Reported by @felipecpaiva in [#131](https://github.com/crmne/hyprmoncfg/issues/131).
- **Another unit of a saved monitor model gets its layout.** Plug in a different monitor of the same make and model, such as a second office's identical screen, and the profile saved for the first one applies to it. A profile that knows the exact unit always wins. Built-in panels are never matched this way, and the other unit's ICC profile and HDR luminance overrides are not copied over. Reported by @IamM47Z in [#126](https://github.com/crmne/hyprmoncfg/issues/126).

## Fixed

- **Displays wake after resume on Hyprland 0.56 with a Lua config.** The resume wake sent the legacy `dpms on`, which Hyprland 0.56 wraps into invalid Lua and rejects. hyprmoncfg now resends it in Lua when the legacy form is rejected, and a `.lua` Hyprland config selects Lua from the start. Reported by @iamalanabreu in [#125](https://github.com/crmne/hyprmoncfg/issues/125).

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart `hyprmoncfgd.service`. Upgrade every machine that shares your profiles before saving one with Per display: hyprmoncfg 1.29 and older reject the new strategy and drop the per-display count. The Omarchy panel offers Per display and the count from version 2.16.0, and only with this daemon. The workspaces bar widget shows each display's own workspaces from version 0.3.0.

## Known limitations

- Per display was tested live on Omarchy 4.5. Without Omarchy, the generated bindings were checked by Hyprland and run against a stand-in for its Lua API, but not yet in a live session on another distribution. Reports are welcome.
- Window rules for a specific display still use Hyprland's numbers: workspace 12 is the second workspace of the second display.
- The TUI's profile detail still draws a display matched through another unit of the same model as not connected, although the profile applies to it.

## What's tested

The full Go suite and vet pass, including Lua runtime tests of the generated per-display bindings with and without Omarchy and for every count. Hyprland 0.56.2 accepted the generated Lua and hyprlang configs with `--verify-config`. On a laptop running Omarchy 4.5 with an external display, Per display handed over to Omarchy, the planner matched the blocks Omarchy assigned, `hyprmoncfg workspace` switched in about 40 ms, and both `hyprmoncfg scale` and Omarchy's own scale script saved the new scale to the profile. The other-unit match and the Lua wake retry were tested against fixtures, not on the reporters' hardware.
