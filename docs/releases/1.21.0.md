# hyprmoncfg 1.21.0

A laptop whose external display comes back without a picture now lights its own screen instead of staying dark, and the TUI shows which displays aren't working as saved. Install from the AUR or download a package below. Pair it with [panel 2.5.0](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.5.0) for Omarchy, which shows the same information.

![The TUI layout with a display that has no usable signal and one running below its saved settings](https://raw.githubusercontent.com/crmne/hyprmoncfg/v1.21.0/docs/assets/images/releases/1.21.0-display-health.png)

*Synthetic displays, rendered offscreen.*

## New

- **The TUI names displays that aren't showing a picture.** A display that's on but has no mode used to show up as a tiny empty card, or not at all in a small window. It now gets its own row, marked **No usable signal**, next to the rows for displays that are off or mirrored.
- **The TUI says when a display runs below its saved settings.** If the daemon stepped a display down because it wouldn't stay on at its saved settings, its card now says how it runs, for example `running at 120 Hz without VRR`. Your saved profile is unchanged.

## Fixed

- **A laptop no longer stays dark when its external display comes back without a picture** ([#67](https://github.com/crmne/hyprmoncfg/issues/67)). With the laptop screen off, some external displays come back from a power cycle with no mode and stay black until another output lights up. Stepping down their refresh rate doesn't help. The laptop screen may now stay off only while an external display actually shows a picture. Otherwise the daemon turns it on, to the right of your other displays, and turns it off again once the external has a picture. That holds whether the lid is closed or your profile turns the laptop screen off. Reported by @itsDamon.
- **Displays aren't stepped down for the wrong reason.** While no display shows a picture at all, a display without a mode no longer counts against its saved refresh rate. On the laptop in #67 this had taken the external down to 60 Hz for nothing.

## Known limitations

- **Not yet tried on the hardware from #67.** Automated tests cover the laptop screen coming on, staying on while the external is still coming back, and the step-down staying out of it.
- **A display that stays connected but shows "No signal" is still invisible to hyprmoncfg.** Hyprland and the kernel report it the same as a working display.
- **"No usable signal" doesn't yet say whether recovery is in progress.**

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

The IPC protocol is still version 1.
