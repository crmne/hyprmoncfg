# hyprmoncfg 1.22.0

The TUI has a new look. Your displays sit on a stage as screens, with their workspaces as chips, and dragging them now behaves exactly as in the Omarchy panel: they snap into place and can never overlap. With the lid closed on a dock, your saved clamshell profile now wins. Install from the AUR or download a package below. Pair it with [panel 2.6.0](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.6.0) for Omarchy, redesigned alongside it.

![The redesigned TUI layout: displays on a dotted stage with workspace chips, hardware details under the canvas, and inline choices for Enabled and VRR](https://raw.githubusercontent.com/crmne/hyprmoncfg/v1.22.0/docs/assets/images/releases/1.22.0-tui-stage.png)

## New

- **The layout is a stage.** The dense grid is gone. Each display is a card with its connector and model at the top, its workspaces as chips, and its mode, scale and position at the bottom. The selected display gets a heavy border, so you don't need colour to see it. Hardware details move to a box under the canvas, and Display and Color get the whole right column.
- **Workspaces and Profiles show the canvas on top,** with the plan or the profile details below it, as in the panel.
- **Scale presets, as in Omarchy.** Scale is a row of preset pills, 1x, 1.25x, 1.5x, 1.6x, 2x and 3x, each adjusted to the nearest sharp scale above it for that display. More lists every sharp scale, and Custom takes a typed value. A scale that isn't one of the presets keeps its own pill. The arrow keys now step through the same sharp scales the panel offers, starting at 1x.
- **Quicker settings.** Enabled, VRR, colour depth, SDR EOTF and the WCG and HDR overrides show every choice in a row you can pick with a key or a click. Position X and Y are typed in place.
- **Keep or revert, at a glance.** The confirmation after a preview now reads "Keep this layout?", shows a draining countdown and a small picture of the layout, and has clickable Keep and Revert buttons. It stays usable down to a 60x12 terminal.

## Fixed

- **Displays can no longer overlap in the TUI.** Dropping a display snaps it to its neighbours' edges and alignments. If it would still cover another display, it moves to the nearest clear edge, or back to where you picked it up. Arrow keys, typed positions and other edits that would create an overlap are refused with the reason, for example "DP-2 would overlap DP-1". The TUI and the panel now use the same placement code, checked against 2000 random layouts.
- **Dragging no longer lags behind the pointer.** The canvas used to re-fit itself while you dragged, so a long drag ended far from where you let go. It now holds still during a drag, and the display lands exactly under the pointer.
- **With the lid closed on a dock, your clamshell profile wins** ([#76](https://github.com/crmne/hyprmoncfg/issues/76)). A profile that turns the laptop screen on used to outscore the clamshell profile saved for exactly this setup, so the daemon applied the wrong positions and workspaces. With the lid closed and an external connected, a profile that keeps the laptop screen off now scores higher. The score breakdown names the new reasons: "built-in, kept off with the lid closed" and "built-in, turned off by the closed lid". Reported by @brdweb.
- **A display without a picture no longer blocks your layout.** A display that's on but has no mode could be reported as overlapping the display at 0,0 ("layout overlaps: HDMI-A-1 intersects DP-1"). It now takes up no space.

## Known limitations

- **Snapping is coarser in a terminal.** The smallest pointer step is one terminal row, so drops snap from further away than in the panel.
- **A layout that already overlaps,** for example one saved that way, can still be edited in the TUI so you can untangle it. The panel refuses edits until it's fixed.
- **Identify, a profile action menu and per-field reset** are still panel-only.
- **The redesign was used on the maintainer's desktop, but the lid-closed matching and the no-picture fix are covered by automated tests only,** not yet on the hardware from #76.

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

The IPC protocol is still version 1.
