# hyprmoncfg 1.28.0

Keep a 2-in-1's upright rotation when you leave Auto, calibrate without the CLI, and stop Omarchy's migration from stranding your wake settings.

Download the [Linux x86-64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.28.0/hyprmoncfg_1.28.0_linux_amd64.tar.gz) or [Linux ARM64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.28.0/hyprmoncfg_1.28.0_linux_arm64.tar.gz). On Arch, install `hyprmoncfg-bin` from the AUR.

## New

- **Calibrate from the TUI.** Hold the device upright and press `C`. The CLI now tells you what to do if the screen is still sideways afterwards. The Omarchy panel gets the same action in its next release.

## Fixed

- **Auto, Normal, Auto no longer loses a sideways panel's upright rotation.** A panel whose upright rotation is 270° gets it back when you return to Auto. Choosing another fixed rotation first still replaces it, and the [two-in-one guide](https://hyprmoncfg.dev/two-in-one/) explains how to go back to Normal. Reported by @xpusostomos in [#90](https://github.com/crmne/hyprmoncfg/issues/90).
- **Omarchy's config migration no longer stops wake settings from syncing.** It could move hyprmoncfg's block to the end of `monitors.lua`. An exact copy of the block now moves back to the top on the next apply. A block that differs is left alone with the same warning. Reported by @CAI991108 in [#110](https://github.com/crmne/hyprmoncfg/issues/110).

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart `hyprmoncfgd.service`.

## Known limitations

- Normal still means the panel's hardware orientation, not your calibrated upright. Fixed rotations are not relative to calibration.
- If the panel's geometry changes while the wake block is stranded, the block no longer matches and stays put until you move or delete it.

## What's tested

The full test suite passes. Rotation memory and calibration were tested in unit tests only, not on a real 2-in-1. The wake fix was tested on a fixture of the file layout the migration produces, not by running the migration.
