# hyprmoncfg 1.20.2

A quieter install. This release works with [panel 2.4.1](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.4.1) for Omarchy; the panel doesn't need an update.

## No more "Permission denied" after building from source

Building hyprmoncfg from the AUR with yay, or with `makepkg -c`, used to end with a long list of `rm: cannot remove ... Permission denied` lines. The install itself worked. The errors came from the offline Go dependency archive that each release ships: Go marks those files read-only, so the build's own clean-up couldn't delete them.

The archive now ships them writable, and clean-up works. Go still checks every dependency against `go.sum`, so nothing changes in what gets built.

If you still have leftovers from an earlier build, clear them once:

```sh
chmod -R u+w ~/.cache/yay/hyprmoncfg/src && rm -rf ~/.cache/yay/hyprmoncfg/src
```

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

Nothing else changed since 1.20.1.

## What's tested

A test archive built with the new script has writable folders, builds offline, and is removed by a plain `rm -rf`. The release's packaging checks passed.
