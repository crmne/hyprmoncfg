# hyprmoncfg 1.25.0

Calibrate a tablet's upright sensor position, keep touch aligned with fixed panel rotations, and recover monitors that wake at different speeds. The companion [panel 2.10.0](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.10.0) explains rotation previews and lets source-package users switch to prebuilt updates.

Download the [Linux x86-64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.25.0/hyprmoncfg_1.25.0_linux_amd64.tar.gz) or [Linux ARM64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.25.0/hyprmoncfg_1.25.0_linux_arm64.tar.gz), or install hyprmoncfg-bin from the AUR.

## New

- **Teach the sensor which way is upright.** Hold the device upright and run `hyprmoncfg rotation calibrate`. The daemon persists that sensor baseline separately from the profile's panel rotation, so devices with differently mounted sensors can use Auto without a permanent offset. Set the correct fixed panel rotation before selecting Auto. Calibration unlocks rotation and is rejected during a preview or without a usable sensor reading. By @crmne; thanks @xpusostomos for [#90](https://github.com/crmne/hyprmoncfg/issues/90).

## Fixed

- **Touch follows fixed built-in-panel rotations too.** Previously the generated touch and pen transform followed only Auto. Fixed rotation now writes the same alignment for a connected, enabled internal panel. By @crmne; thanks @xpusostomos for [#90](https://github.com/crmne/hyprmoncfg/issues/90).
- **A partly awake setup keeps recovering.** Explicit wake retries continue until the intended enabled outputs are usable and awake, within the bounded recovery window. Failed monitor readback keeps the wake pending, and closing the lid cancels an outstanding wake. Disabled and mirrored outputs do not hold up recovery. By @jualvarez in [#95](https://github.com/crmne/hyprmoncfg/pull/95), with readback and lid-close follow-ups by @crmne.
- **Preview confirmation explains why Auto pauses.** The TUI now says that Auto rotation resumes after Keep, as does panel 2.10.0. By @crmne; thanks @xpusostomos for [#90](https://github.com/crmne/hyprmoncfg/issues/90).

## Upgrading

Update both hyprmoncfg and hyprmoncfgd, then run `systemctl --user restart hyprmoncfgd.service`.

The IPC protocol remains version 1. Calibration uses an advertised capability; a new CLI refuses calibration against an older daemon instead of silently sending an unsupported operation.

## Known limitations

- Sensor calibration and rotation direction are CLI controls; the panel exposes Auto and Lock.
- Touch and pen alignment uses Hyprland's global transform settings, not per-device calibration for multiple independent touch displays.
- The rotation changes and partial-wake recovery have deterministic regression coverage, but this release has not been tested on a physical 2-in-1 or by triggering a physical partial wake.

## What's tested

The full Go test suite, vet, builds, dependency checks, and daemon/IPC race tests pass. Regression tests cover calibration persistence and rejection, older-daemon capability handling, fixed-panel touch alignment, preview guidance at small terminal sizes, incomplete wakes, failed readback, and lid-close cancellation. No live monitor layout was changed for these checks.
