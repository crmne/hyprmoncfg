# hyprmoncfg 1.19.2

A fix for displays that flicker on and off when you turn them back on. This release works with [panel 2.4.1](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.4.1) for Omarchy; the panel doesn't need an update.

## Displays come back on in one go

Turning a display off and on again could make it switch on and off several times before settling, or give up and stay dark. This happened with displays that take a few seconds to wake, such as the MSI MPG321UR-QD.

While the display was off, hyprmoncfg rewrote its generated monitor file without that display's rule. When the display came back, Hyprland started it in a default mode, and a second later hyprmoncfg switched it to the mode saved in your profile. That second switch hit the display while it was still waking up, and it dropped off again.

Now the generated file keeps the rule for a display in your profile while it's off or unplugged, so Hyprland sets the saved mode straight away. The rule names the display by its hardware description, never by the port it was plugged into. Displays that can't be told apart that way, such as two identical models, are left out, so a rule never lands on a different display.

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

The IPC protocol is still version 1.

## What's tested

Automated tests cover the generated file for Lua, `monitorv2` and legacy `monitor =` configs, and every case where a disconnected display is left out. The failure was traced in the daemon and Hyprland logs on an MSI MPG321UR-QD. The fix itself hasn't yet been tried by turning that display off and on again.
