# hyprmoncfg 1.27.0

Work alongside Omarchy's new display panel, land hotplugged displays about four times faster, and rename your saved profiles.

Download the [Linux x86-64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.27.0/hyprmoncfg_1.27.0_linux_amd64.tar.gz) or [Linux ARM64 binaries](https://github.com/crmne/hyprmoncfg/releases/download/v1.27.0/hyprmoncfg_1.27.0_linux_arm64.tar.gz). On Arch, install `hyprmoncfg-bin` from the AUR.

## New

- **Omarchy's display panel and hyprmoncfg no longer overwrite each other.** Omarchy reapplies its saved settings when a monitor arrives, after your generated config has loaded, so loading last was not enough. The generated Lua file now turns that off, and takes over `GDK_SCALE` from the lowest active scale.
- **Edits in Omarchy's panel are kept.** When you change a display there, the daemon folds the change into your active profile instead of reverting it. An edit for an unplugged monitor waits until it returns.
- **Hotplugged displays land much faster.** Plug and unplug events now apply after 300ms instead of 1.2s. In a test with simulated monitors, a display reached its place in about 380ms, down from about 1,480ms. Use `--hotplug-debounce` if your hardware needs longer. If you already set `--debounce`, hotplug keeps using it.
- **Rename saved profiles.** Use `hyprmoncfg rename <old> <new>`, or `r` and **[Rename]** on the TUI's Profiles tab. Rename moves the profile's files and applies nothing. Requested by @shyam-unnithan in [#100](https://github.com/crmne/hyprmoncfg/issues/100).

## Fixed

- **Omarchy's Mirror Display action works while hyprmoncfg manages your monitors.** The generated file now honours its toggle. Reported in [omacom/omarchy#13953](https://github.com/omacom/omarchy/issues/13953).
- **Automatic rotation survives a refused sensor claim at boot.** If polkit refuses the claim before your session is active, the daemon keeps retrying, and `hyprmoncfg rotation` says it is waiting rather than telling you to install iio-sensor-proxy. Reported by @xpusostomos in [#90](https://github.com/crmne/hyprmoncfg/issues/90).

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart `hyprmoncfgd.service`. The panel's Rename action needs a later panel release, and its Omarchy 4.0.6 fix is in panel 2.12.0.

## Known limitations

- Edits to two identical monitors in Omarchy's panel are skipped and logged, because Omarchy numbers them in its own order.
- A panel on automatic rotation keeps its rotation when Omarchy's panel changes it.
- Going from Auto to a fixed rotation and back can still lose a sideways panel's upright rotation. See [#90](https://github.com/crmne/hyprmoncfg/issues/90).

## What's tested

The full Go suite, vet, and race tests for the daemon, orientation, IPC and profiles pass. The panel handoff, hotplug timing and edit import ran against real `hyprmoncfgd` in an isolated nested Hyprland, with position changes only. `GDK_SCALE` and the Mirror Display toggle ran in Lua against a stand-in for Hyprland's API. This release does not claim tests on real docks, real rotation hardware, or Hyprland 0.57, and live edits were tested through a replug rather than the 5-second poll.
