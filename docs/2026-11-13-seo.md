## Technical check (live site, 2026-11-13)

What's right: every sitemap URL answers 200 with one h1, a self-referencing canonical, descriptions under 160 characters, JSON-LD that parses (Organization, WebSite, WebPage, TechArticle, BreadcrumbList), Open Graph and Twitter cards with a PNG og:image that answers 200. http and www redirect to https://hyprmoncfg.dev with 301. No layout shift worth naming (CLS 0 to 0.013), no sideways scroll at 390 px; the home page's LCP is the hero video poster (0.5 s on a phone), and the page weighs about 1 MB because of the video loop. HTML is cached for 10 minutes (GitHub Pages).

What was wrong, and what this pass did:

| Issue | Done |
|---|---|
| Home `<title>` was "hyprmoncfg" only | `seo.title` "Multi-monitor layouts for Hyprland" |
| Getting Started title and description had no topic words | `seo.title` "Getting Started: Hyprland monitor setup", description names Hyprland and the monitor profile |
| Broken link: TUI Walkthrough linked `virtual-desktops.md` (404 on the site) | Now `../virtual-desktops/` |

Proposals:

- **`/next/` is indexable.** The theme publishes the default branch at `/next/` with self-canonicals and `index,follow`, and lists `/next/sitemap.xml` in `robots.txt`, so Google can see two copies of every page. Either `noindex` the `/next/` build or canonicalize each `/next/` page to its stable twin. This belongs in crmne/jekyll-vitepress-theme, for every site that uses versions.
- **`/about/` has no internal links** (it's in the sitemap and the publisher's JSON-LD only). A footer or What is link would help.
- These fixes are on `main`, which the docs workflow publishes at `/next/`. The root shows the latest release tag, so they reach `/` with the next release.
